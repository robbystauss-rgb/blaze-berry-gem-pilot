# Front crown calibration data

`crown-calibrations.json` describes the front panel in every currently selectable exact Richardson model and colorway photograph. These are visual photographic measurements, not measurements in inches. The rectangular reference covers the projected front panel, excluding mesh, button, and brim. The 168 / 168P reference follows the lower front panel below its upper seam. It does not create a placement boundary or mask.

The origin is the top left of the complete source image. X increases rightward and Y increases downward. Bounds use fractions of source width and height in the range 0–1, including any whitespace or transparency in that source. A bound's width and height are independent measurements of the crown photograph; they must never be used to scale the patch's width and height independently.

Each record binds an exact `modelId`, catalog `colorway`, and original catalog `assetId` to an immutable `imageUrl`. The snapshot filename and `sha256` identify its encoded bytes. `sourceSha256` identifies the original downloaded bytes. Front photographs are encoded as lossless WebP without resizing; all 243 snapshots were checked for exact decoded RGBA pixel equality with their original source photographs. `sourceWidth` and `sourceHeight` are the actual sampled image dimensions. Remote sources were sampled at the builder's existing `=w1200` URL; existing local catalog photos keep their actual original dimensions.

All source photographs and their crown overlays were visually inspected on 2026-10-07. Each record reflects its own photograph's panel outline. Distinct framing is preserved: 112FP Pale Khaki/Loden Green is smaller in its source frame, 168 Black and Black/Camo/Loden differ from peers, 112FPR combines 10 frontal photographs with 7 angled catalog photographs, and 112PM / 168P use angled catalog photographs. The 256 and 256P sources also differ in aspect ratio and whitespace. No photograph was substituted between models or colorways.

The calibration identity contains the snapshot's hash prefix. Replacing a photograph requires a new snapshot, a new calibration identity, and inspection of its crown bounds. Merely retaining an old catalog asset name is insufficient. Bounds are recorded to six decimal places; photographic edge measurements are approximate to a few source pixels, and do not claim manufacturing precision.

Run `node scripts/validate-crown-calibrations.mjs` to check current corrected-catalog coverage, exact model/asset identity, finite normalized bounds, all immutable snapshot hashes, and source dimensions. Local original catalog photos are also byte-checked. To compare all remote original sources against a local download cache, append `--source-cache <directory>`; cached files are named with the colorway's colon replaced by `__` and a `.jpg` suffix, regardless of their decoded source format. `--verify-remote` fetches and checks the original remote builder photographs instead. A changed remote original does not silently replace the calibrated immutable snapshot.

The source cache and visual QA images are review artifacts rather than application data. Side and back photographs keep their existing behavior and are outside this front-crown calibration dataset.
